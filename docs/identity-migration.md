# iOS 식별자 Keychain 마이그레이션

`SharedIdentityStore`는 Keychain 조회, UserDefaults 이전, 이후 저장을 동기적으로 처리합니다.
`try store.load()`는 캐시를 먼저 확인하며, 없으면 저장소를 읽습니다.
공용 `Keychain<Value>`는 Codable 값의 읽기·쓰기만 담당하며 실행 큐를 소유하지 않습니다.
식별자를 처음 읽을 때 캐시 확인과 마이그레이션을 수행합니다. 초기화 시 별도의
선로딩 작업을 등록하지 않으며, 저장 완료 콜백이나 Task도 사용하지 않습니다.
`projectID`, `username`, 원본 `deviceID`, `externalUserID`를 공유 Keychain에 저장하며,
JSON 키와 `schemaVersion = 1`, UUIDv5 namespace 및 기존 ID 계산 입력을 유지합니다.
특히 익명 사용자 ID의 기존 Optional 문자열 표현도 유지합니다.

## 이전 순서

1. 프로젝트별 공유 Keychain을 먼저 읽습니다. 값이 있으면 기존 UserDefaults와
   충돌하지 않는지 확인하고, 남아 있는 식별자 키를 삭제한 뒤 해당 값을 사용합니다.
   읽기 실패와 항목 부재는 구분합니다.
2. 공유 항목이 없으면 기존 프로젝트 접두사가 붙은 UserDefaults 값을 읽습니다.
   device ID도 UserDefaults에서 읽으며, 값이 없으면 앱에서 IDFV를 사용합니다.
   기존 앱 전용 Keychain은 조회하지 않습니다. 따라서 그곳에만 남아 있는 device ID는
   복원하지 않으며, 새로 사용하는 IDFV 값과 다를 수 있습니다.
3. 새로운 공유 항목을 추가합니다. 동시에 생성된 기존 항목은 덮어쓰지 않습니다.
4. 캐시를 우회해 다시 읽고 전체 모델이 일치하는지 확인합니다.
5. UserDefaults 원본이 복사 시작 시점과 같은지 확인한 뒤 해당 프로젝트의 식별자
   키 네 개만 삭제합니다. 검증된 모델을 메모리에 공개합니다.

쓰기 후 앱이 종료되어 UserDefaults가 남아 있더라도 다음 실행에서 공유 항목을
검증하고 정리를 재개합니다. 읽을 수 없는 데이터, 지원하지 않는 스키마, 명시적으로
충돌하는 식별자는 자동으로 초기화하거나 덮어쓰지 않습니다.

## 이후 읽기와 변경

- 기존 `AsyncWorker`에서 시작한 SDK 작업은 그 안에서 Keychain을 동기 호출합니다.
  `user-state` 응답은 URLSession 응답 콜백에서 직접 처리하며 워커에 다시 넣지 않습니다.
- `getNotiflyUserId()`와 `AppHelper`의 직접 조회는 캐시가 없으면 호출한 스레드에서
  Keychain을 읽습니다. 메인 스레드에서는 저장소 접근만큼 지연될 수 있으며,
  해당 함수의 주석에 이를 명시합니다. 캐시가 있으면 Keychain을 다시 읽지 않습니다.
- 여러 호출이 겹칠 때 조회·마이그레이션·저장·캐시 갱신이 뒤섞이지 않도록
  식별자 저장소의 동기 작업을 잠금으로 보호합니다. 잠금은 스레드를 전환하지 않으며,
  다른 저장 작업이 진행 중이면 직접 조회도 그 작업이 끝날 때까지 기다릴 수 있습니다.
- IDFV는 저장소 등록 시 잠금을 잡기 전에 준비하고, 기존 식별자가 모두 없을 때만
  사용합니다. Keychain 잠금을 보유한 채 메인 큐를 기다리는 순환 대기를 피합니다.
- 로그인·로그아웃과 서버의 사용자 매핑 변경은 저장·재조회 성공 후 반영합니다.
  저장 실패 시 이전 값을 유지하며, 쓰기 성공 후 검증이 실패하면 불확실한 캐시는
  비웁니다. 읽기 오류를 항목 부재로 처리하거나 임시 식별자를 만들지 않습니다.
- 첫 조회가 실패하면 이후 조회에서 재시도할 수 있습니다. 실패한 이벤트를 자동으로
  재전송하는 기능은 포함하지 않습니다.
- 알림 확장은 매 알림의 처리 콜백에서 공유 항목을 다시 읽습니다. 앱의 이전이
  아직 진행되지 않았으면 기존 UserDefaults를 읽되 새 ID를 만들거나 데이터를
  삭제하지 않습니다. 식별자 조회 실패 시에도 알림 콘텐츠 처리는 수행합니다.

## 배포 경계

앱과 Notification Service Extension에 이 버전의 SDK를 함께 적용해야 합니다.
UserDefaults만 읽는 구버전 확장과의 혼합 배포나 구버전 SDK로의 다운그레이드는
지원하지 않습니다. 구버전은 새 Keychain 항목을 읽지 못하기 때문입니다.
롤백이 필요하면 새 Keychain 읽기 경로를 유지한 수정 버전을 배포해야 합니다.

비밀번호·deprecated JWT·APNs 등록 플래그의 정책은 변경하지 않습니다. 예전 앱
전용 Keychain의 device ID는 조회·수정·삭제하지 않습니다. 공유 접근 그룹은 기존
`group.notifly.{username}`을 사용하며 다른 그룹으로 자동 대체하지 않습니다.

시뮬레이터에서 잠금·권한·쓰기 실패는 테스트 대역으로 재현하고, 실제 Security API는
전용 테스트 앱 사이에서 검증합니다. 실기기의 재부팅 직후 잠금 상태, 실제 NSE 실행,
고객사 서명·프로비저닝은 별도 릴리스 검증 대상입니다.
